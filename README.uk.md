# Smart Notify

[![Відкрити репозиторій у HACS у твоєму Home Assistant.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=DmytroZamkovyi&repository=smart_notify&category=integration)

Користувацька інтеграція Home Assistant: **одна служба сповіщень** для
скриптів та автоматизацій, а кожна людина сама обирає, **куди** отримувати
сповіщення за кожною категорією.

```yaml
action: notify.smart
data:
  user: person.alice        # необов'язково; можна список
  category: security        # категорія, яку ти створив
  title: Рух у дворі
  message: Камера біля воріт
  data:                     # необов'язково, передається в канал
    image: /local/snapshot.jpg
```

Ні допоміжних сутностей, ні налаштувань у YAML: усе робиться в інтерфейсі.

## Можливості

- Одна служба `notify.smart` зі стандартним інтерфейсом notify
  (`message`, `title`, `data`) плюс `user` і `category`.
- **Канали**: телефони (Companion), Telegram-боти, браузери (HTML5 push) та
  будь-який інший `notify`. У кожного каналу є власник (людина або «Загальний»).
- **Категорії та підкатегорії**: створює адмін (безпека, клімат, світло з
  підкатегоріями «зміна графіка» й «екстрені відключення», ...). У формі дії
  вони з'являються випадним списком. Необов'язково: префікс у заголовку,
  типове налаштування адміна (увімкнено чи вимкнено для всіх) і прапорець
  «службова» для категорій лише розробника.
- **Маршрути** окремо для людини й категорії:
  - вимкнено;
  - надсилати **в кілька каналів одразу**;
  - **резервні канали**, які пробуються по черзі, лише якщо жоден основний не
    спрацював (наприклад, Telegram, потім телефон).
- «Панель HA» (персистентне сповіщення) це звичайний канал на вибір.
- Кожна людина налаштовує свої маршрути на сторінці `/smart-notify`
  (без пункту в боковому меню). Адмін може налаштовувати всіх.
- **Стандартний `data`** (`image`, `url`, `actions`, `tag`, `priority`, `format`,
  `sticky`, `clear`, `expire`, `progress`), однаковий для телефона, Telegram і
  браузера; прогрес у Telegram редагується на місці, довгий текст ділиться,
  є термін актуальності й знімки камер.
- **Тихі години** для кожної людини (розклад і/або умова для сутності), різна
  поведінка за пріоритетом, відкладена доставка зі зведеннями; вікно дублікатів;
  журнал; кнопка тесту.
- Дія повертає результат доставки; отримувачів можна фільтрувати за присутністю.
- Тільки штатний інтерфейс: записи з підзаписами, жодного YAML.

## Вимоги

- Home Assistant з підтримкою підзаписів конфігурації (2025.3 і новіше).
  Перевірено на 2026.10.
- Для браузерних сповіщень: інтеграція HTML5 Push Notifications і зовнішня
  HTTPS-адреса.

## Встановлення

HACS: натисни кнопку вгорі сторінки або додай репозиторій вручну:

1. HACS, Інтеграції, три крапки, Власні репозиторії.
2. Додай цей репозиторій, категорія Integration.
3. Встанови Smart Notify і перезапусти Home Assistant.

Вручну:

1. Скопіюй вміст цього репозиторію в папку `smart_notify` усередині
   `config/custom_components/`, щоб існував файл
   `config/custom_components/smart_notify/manifest.json`.
2. Перезапусти Home Assistant.

Далі: Налаштування, Пристрої та служби, Додати інтеграцію, **Smart Notify**.
З'являться два блоки:

- **Smart Notify · Канали**: тут додаються канали.
- **Smart Notify · Категорії**: тут додаються категорії та налаштовуються
  маршрути.

## Налаштування

1. Блок **Канали**, «Додати канал»: що підключити, назва, власник. Один канал
   на кожен телефон, Telegram-бота чи браузер.
   - Власник = людина: канал використовується лише в маршрутах цієї людини.
   - Власник = «Загальний»: канал використовується, коли `notify.smart`
     викликано без `user`.
2. Блок **Категорії**, «Додати категорію»: ідентифікатор (латиниця, цифри,
   `_`) для скриптів і назва. Необов'язково: батьківська категорія (робить її
   підкатегорією), префікс у заголовку, типово для всіх, прапорець «службова».
3. Маршрути, на вибір:
   - кожна людина відкриває `/smart-notify` під своїм обліковим записом
     (він має бути прив'язаний до `person`);
   - або адмін через шестірню блоку «Категорії».

## Правила маршрутизації

- Налаштування категорії: **Як у загальному маршруті**, **Вимкнено** або
  **Надсилати**. У кожної людини є ще загальний маршрут, від якого категорії
  успадковують налаштування.
- **Надсилати**: у всі канали зі списку «Надсилати в» одразу. Канали зі списку
  «Якщо не доставлено» пробуються по черзі в порядку вибору, лише якщо жоден
  основний не спрацював, і зупиняються на першому успішному.
- Нічого не налаштовано: використовується персистентне сповіщення в панелі HA,
  тому повідомлення не губиться мовчки.
- Якщо жоден вибраний канал не спрацював, помилка пишеться в журнал, а
  повідомлення йде в панель HA як останній варіант.
- Без `user`: усі «Загальні» канали; якщо їх немає, усім людям.
- `user: all` надсилає кожній людині.
- Один канал за один виклик не використовується двічі.
- `category` обов'язкове. Невідома категорія або категорія, що має
  підкатегорії, завершує дію помилкою (видно в трасі автоматизації).

## Підкатегорії, типові налаштування й префікс

Категорія з підкатегоріями є лише **групою**: на неї надсилати не можна, вона
задає спільні налаштування для своїх підкатегорій. У скриптах вказується
ідентифікатор підкатегорії, наприклад `category: emergency_outage`, а не
`power`. Підтримується один рівень вкладеності, ідентифікатори унікальні серед
категорій і підкатегорій.

Яке налаштування діє для людини (береться перше, що збіглося):

1. Власне налаштування людини: підкатегорія, потім категорія (перше, де не
   «Як у ...»). **Вимкнено** означає тишу, **Надсилати** означає канали
   людини. Підкатегорія з **Надсилати** перемагає, навіть якщо її категорія
   **Вимкнено**.
2. Типове налаштування адміна: підкатегорія, потім категорія. **Вимкнено для
   всіх** означає тишу, доки людина явно не обере **Надсилати** (для категорії
   `dev` лише для розробника разом із прапорцем «службова», який ховає її від
   користувачів на сторінці налаштувань).
3. Загальний маршрут людини.
4. Нічого не налаштовано або всі канали впали: персистентне сповіщення в
   панелі HA. Свідоме **Вимкнено** його ніколи не створює.

**Префікс**: префікси категорії й підкатегорії склеюються в дужках, наприклад
`[Світло][Екстрені]`, і ставляться перед заголовком. Без `title` заголовком
стає сам префікс, а `message` лишається як був. Шаблони в `title`, `message` і
`data` працюють як завжди (Home Assistant обчислює їх до виклику дії); сам
префікс це звичайний текст.

Якщо видалити категорію з підкатегоріями, вони стають звичайними категоріями
верхнього рівня, а сповіщення про це з'явиться в панелі (Home Assistant не дає
заборонити таке видалення).

## Оновлення до 5.0

`category` тепер обов'язкове, а невідома категорія дає помилку (раніше було
попередження в журналі). Скрипти, що викликають `notify.smart` без категорії
або з неіснуючою категорією, треба виправити. Наявні категорії й маршрути
працюють без міграції.

## Стандартний `data`

Один `data` працює для всіх каналів; кожен канал перетворює його у свій
формат. Ключі, яких немає в цьому списку, вважаються специфічними для каналу й
передаються далі як є.

| Ключ | Що означає |
|---|---|
| `image` | Одна картинка для всіх каналів: посилання, `/local/file.jpg` (`config/www`), `/media/...` або шлях до файлу, або `{camera: camera.gate}` для знімка камери |
| `url` | Відкривається по натисканню (телефон) або кнопкою «Відкрити» (Telegram, браузер) |
| `actions` | Кнопки: `{title, id}` або кнопка-посилання `{title, url}` |
| `tag` | Замінює попереднє сповіщення з таким самим тегом |
| `priority` | `low`, `normal`, `high`, `critical` |
| `format` | `plain` (типово), `html`, `markdown` (Telegram) |
| `sticky` | Сповіщення не зникає від дотику |
| `clear` | Разом із `tag`: прибрати це сповіщення з телефона |
| `expire` | Термін актуальності: секунди або `30m`, `2h`, `1d` |
| `progress` | `0..100` або `{value, max}` |

| Канал | Відповідність |
|---|---|
| Телефон | `image`, `tag`, `sticky`, `progress`, `actions` (кнопки-посилання як `URI`), `url` як `clickAction`; значок категорії стає `notification_icon`, назва категорії стає `channel` і `group`; `priority` стає важливістю Android / рівнем переривання iOS |
| Telegram | Текст або фото; заголовок жирним для `html`/`markdown`; `actions` і `url` стають кнопками під повідомленням; `priority: low` і «без звуку» тихих годин надсилаються без звуку; старі ключі (`photo`, `caption`, `parse_mode`, `inline_keyboard`, `keyboard`, `disable_notification`, ...) працюють |
| Браузер (HTML5) | `image`, `tag`, `actions`, `url`, `sticky`/`high` як require-interaction, `expire` як TTL |
| Інші служби `notify` | `data` передається як є |
| Інші сутності `notify` | `data` відкидається, лише `title` і `message` |

```yaml
action: notify.smart
data:
  user: person.alice
  category: security
  title: Рух у дворі
  message: Камера біля воріт
  data:
    image: {camera: camera.gate}
    priority: high
    tag: gate-motion
    expire: 30m
    actions:
      - {title: Камери, url: "https://example.invalid/cameras"}
```

### Telegram докладніше

- Текст понад 4096 символів ділиться на кілька повідомлень; із картинкою підпис
  обмежений 1024 символами, решта йде окремими повідомленнями.
- **Прогрес**: перший виклик із `progress` надсилає повідомлення зі смугою
  (`▓▓▓░░░░░░░ 30%`); наступні з тим самим `tag` редагують його на місці. На 100%
  повідомлення редагується до повної смуги (не видаляється), а завершальний
  текст надсилається новим повідомленням. Без `tag` ключем є категорія.
- **Expire**: після `expire` сповіщення на телефоні очищається, а повідомлення в
  Telegram редагується так, що починається з «НЕАКТУАЛЬНО» (не видаляється).
- Знімок камери для Telegram зберігається у тимчасовий файл у медіа-папці HA й
  видаляється одразу після надсилання.

## Отримувачі й результат

Додаткові поля: `presence` (`any`, `home`, `away` за станом `person`) і `exclude`
(кого пропустити). Дія повертає відповідь із результатом доставки по людях і
каналах (`sent`, `failed`, `off`, `filtered`, `duplicate`, `quiet_skipped`,
`deferred`):

```yaml
action: notify.smart
data: {category: security, message: Перевірка}
response_variable: res
```

## Тихі години

Кожна людина налаштовує свої тихі години на сторінці `/smart-notify`: кілька
інтервалів на добу, обрані дні тижня, від і до (також через північ), та/або
динамічна умова для будь-якої сутності (наприклад, датчик сну чи режиму
фокусу на телефоні). Що відбувається під час тихих годин, залежить від
пріоритету (типові значення):

| Пріоритет | Типово | Варіанти |
|---|---|---|
| `low` | пропустити | пропустити, без звуку, відкласти |
| `normal` | відкласти | пропустити, без звуку, відкласти |
| `high` | без звуку | пропустити, без звуку, відкласти |
| `critical` | завжди доставляється | |

Відкладені сповіщення зберігаються (і після перезапуску) та віддаються, коли
тихі години закінчуються (перевіряється щохвилини): до 3 на категорію по
одному з початковим часом, більше одним зведенням на категорію. Відкладене, що
пережило свій `expire`, відкидається; без `expire` типовий термін 24 години
(Параметри, «Загальні налаштування»).

## Дублікати, журнал, тест

- **Дублікати**: у категорії є поле «Не повторювати однакове сповіщення
  протягом (хв)». Однакові заголовок і текст тій самій людині пропускаються
  (`duplicate`). Повідомлення з `progress` чи `clear` дублікатами не вважаються.
- **Журнал**: останні 200 сповіщень і їхні результати; адмін бачить їх на
  `/smart-notify`.
- **Тест**: кнопка «Надіслати тест» на `/smart-notify` надсилає за справжніми
  маршрутами й тихими годинами людини для обраних категорії та пріоритету.

## Оновлення до 5.1

Ламаючих змін немає. Наявні ключі `data` працюють. Тихі години й вікна
дублікатів вимкнені, доки їх не налаштуєш.

## Браузер (HTML5 push)

1. Додай інтеграцію HTML5 Push Notifications.
2. Відкрий Home Assistant за зовнішньою HTTPS-адресою в браузері, який
   підписуєш.
3. Профіль користувача, «Цей браузер», увімкни сповіщення, назви пристрій,
   дозволь.
4. З'явиться сутність `notify`. Додай її каналом у Smart Notify і вкажи
   власником людину, що користується цим браузером.

Кожен підписує свій браузер і отримує власний канал.

## Обмеження

- Для Telegram і браузерних сповіщень спершу мають бути налаштовані відповідні
  інтеграції.
- Видалення каналу, який є в маршруті, змушує маршрут його пропускати (у
  журнал пишеться попередження).
- Сторінка `/smart-notify` потребує, щоб користувач HA був прив'язаний до
  `person`.
